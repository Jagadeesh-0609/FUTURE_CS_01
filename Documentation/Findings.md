# Vulnerability Assessment Findings

**Target:** http://testasp.vulnweb.com  
**Assessment Type:** Passive / Read-Only Configuration Audit  
**Date:** November 2026  

---

### Finding 1: Plaintext HTTP Communication (No HTTPS / HSTS)
- **Severity:** Medium
- **Description:** The website operates solely over cleartext HTTP on port 80 without SSL/TLS encryption or HSTS enforcement.
- **Impact:** Transmitted data, form inputs, and authentication cookies can be intercepted in transit on untrusted networks.
- **Remediation:** Implement a TLS certificate, configure an HTTP-to-HTTPS redirect, and enforce `Strict-Transport-Security: max-age=31536000; includeSubDomains`.

---

### Finding 2: Content Security Policy (CSP) Header Not Set
- **Severity:** Medium
- **Description:** The web server does not provide a `Content-Security-Policy` HTTP header.
- **Impact:** Browsers cannot restrict the sources from which scripts, frames, or styles are loaded, increasing vulnerability to Cross-Site Scripting (XSS) and data exfiltration.
- **Remediation:** Define a restrictive `Content-Security-Policy` header (e.g., `default-src 'self'`).

---

### Finding 3: Missing Anti-Clickjacking Protection (`X-Frame-Options`)
- **Severity:** Medium
- **Description:** The response does not define `X-Frame-Options` or a CSP `frame-ancestors` directive.
- **Impact:** Malicious domains can embed the application within an invisible frame to manipulate user clicks.
- **Remediation:** Add `X-Frame-Options: SAMEORIGIN` (or `DENY`) across all HTTP responses.

---

### Finding 4: Insecure Cookie Flags (Missing `HttpOnly` and `SameSite`)
- **Severity:** Low
- **Description:** Cookies generated by the application lack the `HttpOnly` and `SameSite` flags.
- **Impact:** Scripts can read cookie values in the document context, and requests sent from cross-site contexts can trigger automated cookie transmission.
- **Remediation:** Set `HttpOnly; SameSite=Lax; Secure` flags on all session and sensitive cookies.

---

### Finding 5: Missing MIME-Sniffing Protection (`X-Content-Type-Options`)
- **Severity:** Low
- **Description:** The `X-Content-Type-Options: nosniff` header is missing.
- **Impact:** User-uploaded or dynamic files may be interpreted as executable scripts by browsers guessing MIME types.
- **Remediation:** Include `X-Content-Type-Options: nosniff` in web server configuration files.

---

### Finding 6: Information Disclosure via Response Headers
- **Severity:** Low
- **Description:** The server exposes infrastructure components (`Server: Microsoft-IIS/8.5`, `X-Powered-By: ASP.NET`).
- **Impact:** Gives attackers immediate insight into the underlying OS and framework versions without extensive fingerprinting.
- **Remediation:** Disable banner broadcasts in `web.config` and strip unnecessary software headers.
